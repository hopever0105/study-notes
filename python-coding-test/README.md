# 파이썬 코딩테스트 공부

퀀트 회사 코딩 시험(알고리즘 문제)을 준비하며 단원별로 정리한 코드.
알고리즘 문제는 시험 환경에 맞춰 **패키지 없이 기본 파이썬만** 쓴다. pandas 분석은 별도 폴더에서.

## 문제 파일 구성
각 문제 파일은 위에 문제(조건·예시), 아래 `#%%` 구역에 내 풀이가 있다. Spyder에서 `Ctrl+Enter`로 구역별 실행.

## 틀렸던 것
| 단원 | 실수 | 고친 방법 |
|---|---|---|
| 반복문·리스트 | 예시 답만 맞추면 된다고 생각 (길이 5면 2를 반환) | 채점기는 숨은 테스트를 넣는다 → 어떤 입력에도 맞는 규칙(반복문)을 짠다 |
| 반복문·리스트 | `2 * [numbers]` — 리스트에 숫자를 곱하면 원소가 아니라 리스트가 반복됨 | `for x in numbers: answer.append(x * 2)` 또는 `[x * 2 for x in numbers]` |
| 반복문·리스트 | `append(x = x*2)` — 함수 괄호 안에 `=`를 씀 → TypeError | 괄호 안엔 붙일 값만: `append(x * 2)` |
| 문자열 | `for x in []` — 입력 대신 빈 리스트를 돌림 | 함수 입력 이름(`codes`)을 그대로 돌린다 |
| 문자열 | 문자열을 `split` 없이 `for`로 돌림 → 한 글자씩 나옴 | `for p in orders.split(","):` |
| 문자열 | `return`을 `for` 안에 둠 → 첫 바퀴에서 끝남 | `return`은 `for`와 같은 높이(반복이 끝난 뒤) |
| 조건문 | `else` 뒤에 조건을 붙임 (`else num1 != num2:`) → SyntaxError | `else:`는 조건 없이, 조건이 필요하면 `elif` |
| 조건문 | `math.gcd()` 괄호를 비워 둠 → 0이 나와 0으로 나누기 에러 | `math.gcd(top, bottom)`처럼 재료를 넣는다 |
| 조건문·딕셔너리 | `count[x+1]` — 키에 1을 더함 → 없는 키라 KeyError | 꺼낸 횟수에 더하기: `count[x] + 1` 또는 `count.get(x, 0) + 1` |
| 조건문·딕셔너리 | 들여쓰기 칸 수가 섞임 → IndentationError | 함수 안 4칸, `for`·`if` 안 8칸, Tab과 스페이스 섞지 않기 |
| 조건문 | `answer = '"급등"'` — 따옴표를 두 겹 써서 글자 안에 `"`가 들어감 | 예시 표의 `"급등"`은 문자열 표시일 뿐 → `answer = "급등"` |
| 조건문·딕셔너리 | 함수를 `count_orders(orders) = ...`로 만듦(def 없음), `orders[]` 빈 괄호 | 함수는 `def 이름(입력):` + 안에서 `return`. 개수 세기는 빈 딕셔너리 + for + `in` 검사 |
| 문자열 | `split(my_string, '')` — split을 함수처럼 씀, 빈 칸으로 쪼개려 함, 리스트 `* n`으로 글자마다 반복하려 함 | 문자열은 `for ch in s`로 바로 한 글자씩, `answer = answer + ch * n` |
| 기초문법 | 될 때까지 반복해야 하는데 `if`를 씀 → 한 번만 검사 | `while 조건:` |
| 기초문법 | `i = answer` — 값 넣는 방향 거꾸로 | `=`는 오른쪽 값을 왼쪽에 넣음 → `return i` |
| 기초문법 | `import math` 후 `mean()` → mean은 math에 없음 | `sum(x) / len(x)` 또는 `statistics.mean(x)` |

## 문제 출처
문제지는 프로그래머스 Lv.0 유형을 참고해 주가·주문 소재로 직접 만든 것(`문제지/`).
연습: 프로그래머스 '코딩테스트 입문' 100문제(Day 1~25). 프로그래머스 문제는 원문 대신 한두 줄 요약만 적음.

## 정리 방식
공부 파일은 `정리전/`에 모아 두고 일주일에 한 번 단원별로 옮겨 이 저장소에 올린다.
